# Deployment Route Recovery Standard

## Purpose

Prevent production 404s caused by a mismatch between TanStack Start's file-based route tree and deployment configuration.

## Required invariants

1. Every public application route is authored under `src/routes/`.
2. Every server route intended to be public is a TanStack Start route with `createFileRoute` under `src/routes/**`.
3. `src/routeTree.gen.ts` is generated by the build and must include the public route set.
4. Vercel must use explicit `framework: tanstack-start` detection.
5. Build output must be generated by the TanStack Start + Nitro Vercel integration; no hand-written rewrites may shadow the framework output.
6. Production smoke tests must request `/`, `/api/health/live`, `/api/health/ready`, and every declared public API route.
7. A 404 on `/` is a release-blocking P0 incident.

## Route ownership

`src/routes/**` is authoritative for HTTP routing. Legacy `src/server-routes/**` is not a second route authority. New endpoints must not be added there.

## Verification

Before release:

```text
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm audit:routes
```

Then validate the deployed artifact:

```text
GET /                         -> 200 HTML
GET /api/health/live         -> 200 JSON
GET /api/health/ready        -> 200 or an intentional dependency status
```

If `/` returns 404, do not compensate with a catch-all rewrite. Inspect framework detection, build output, route generation, and the deployed commit SHA first.

## Visual recovery

The root route must always render a usable recovery UI for route-not-found and client-render failures. Recovery UI must remain functional without external AI providers.

## Evidence

A deployment is not Production-Verified until the exact deployed SHA has passed build, route smoke tests, and artifact/deployment identity checks.
