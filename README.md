## 1. ¿Qué es Isabella Villaseñor AI?

**Isabella Villaseñor AI** es una arquitectura cognitiva híbrida, descentralizada y profundamente gobernada, concebida como el cerebro operativo y la interfaz territorial del **Gemelo Digital de Real del Monte** (Hidalgo, México). 

Frente a los paradigmas extractivos y mercantilistas de la Inteligencia Artificial corporativa tradicional, Isabella propone una alternativa fundamentada en la **soberanía tecnológica comunitaria, la gobernanza "Zero Trust" y el control ético-humano**. No funciona como un simple chatbot comercial, un wrapper de API externa, ni un modelo de inferencia monolítico; es una infraestructura sociotécnica que integra memoria pentacapa, enrutamiento determinista de seguridad, un ledger criptográfico inmutable, procesamiento de utilidad cuántica y módulos de monetización éticos.

Su doctrina operativa de diseño establece que la automatización nunca debe sustituir a la autodeterminación:  
> *Las inteligencias sugieren, calculan y evalúan; el ser humano decide, aprueba y ejecuta.*

## 2. El Desafío Identificado y la Propuesta de Corrección

### El Problema de la IA Corporativa Tradicional

El desarrollo actual de los sistemas de inteligencia artificial adolece de múltiples fallos estructurales que vulneran la privacidad de los usuarios, debilitan el control humano y explotan de forma desmedida los datos locales:
1. **Extractivismo de Datos**: Extracción descontrolada de datos territoriales y comunitarios sin consentimiento informado, atribución justa, ni beneficios compartidos.
2. **Falta de Trazabilidad y Opacidad**: Los modelos actuales operan como cajas negras. Las decisiones, accesos a APIs o ejecuciones de herramientas críticas no dejan un rastro auditable, impidiendo que el operador o regulador verifique la legalidad y fidelidad del proceso.
3. **Inexistencia de Gobernanza Pre-ejecución**: Los sistemas ejecutan acciones de forma reactiva o autónoma sin pasar por un filtro determinista previo que pueda vetar de inmediato instrucciones maliciosas, inyecciones de prompt o acciones de alto riesgo operativo.
4. **Alucinaciones Presentadas como Certezas**: Los LLMs carecen de autoconsciencia de su fiabilidad, presentando información inexacta o inventada como hechos consumados sin medir el nivel de riesgo del contexto.
5. **Incumplimiento Regulatorio e Inseguridad Jurídica**: La mayoría de las aplicaciones de IA carecen de alineación estructural con normativas como el Reglamento de Inteligencia Artificial de la UE (AI Act), los estándares del NIST, o las recomendaciones éticas globales de organismos multilaterales.

Isabella neutraliza estas deficiencias a través de una arquitectura de seguridad y gobernanza integrada por:

┌──────────────────────────────────────┐     ┌─────────────────────────────────────────────────┐

├──────────────────────────────────────┤     ├─────────────────────────────────────────────────┤
│ Ausencia de Control de Pre-ejecución  │ ──► │ Enrutador C.R.O.W.N. + Malla Hardening de 7 Capas│
├──────────────────────────────────────┤     ├─────────────────────────────────────────────────┤
│ Alucinaciones (Falsa Certeza)        │ ──► │ Clasificación Determinista de Riesgo Operativo │
├──────────────────────────────────────┤     ├─────────────────────────────────────────────────┤

└──────────────────────────────────────┘     └─────────────────────────────────────────────────┘

*   **Malla de Hardening de 7 Niveles**: Un blindaje continuo en el servidor que aplica validación Zod, rate-limiting, cabeceras OWASP, mitigación de jailbreak, aislamiento sandbox y detección de patrones de inyección.
*   **Aegis-X Real-Time Gateway**: Una pasarela de seguridad de doble capa conectada a un motor de inteligencia nativo en Python (`latam-aegis-x`) para escanear eventos de seguridad en tiempo real. En caso de ausencia de dependencias, cuenta con un motor redundante en TypeScript matemáticamente idéntico para garantizar 100% de tolerancia a fallos.
*   **BookPI Cryptographic Ledger**: Un libro mayor de auditoría encadenado por hashes HMAC SHA-256 de forma continua e inmutable, impidiendo el borrado, mutación o alteración de registros operativos.
*   **Gobernanza C.R.O.W.N.**: Un sistema de control que clasifica la criticidad y frena la ejecución mediante *Human-in-the-Loop* (HITL) en caso de superar el umbral de riesgo permitido.

## 3. ¿Qué Hace y Cómo lo Hace?

### ¿Qué hace el sistema?
1.  **Analiza y Sanitiza Entradas**: Filtra toda inyección de comandos, inyección de prompt o fuga de secretos antes de procesar el texto.
2.  **Gestiona el Contexto en 5 Niveles**: Recupera y distribuye la memoria en cinco ámbitos estricta y éticamente segregados (Inmediato, Sesión, Proyecto, Territorial e Histórico).
3.  **Detecta Amenazas en Tiempo Real**: Computa de forma determinista y probabilística un indicador de anomalía sobre cada interacción.
4.  **Ejecuta Acciones Técnicas Seguras**: Lanza herramientas y APIs externas de manera aislada (Orion Engine) bajo supervisión directa.
5.  **Simula Procesamiento Cuántico de Utilidad (QUP)**: Compone y ejecuta circuitos cuánticos mediante un flujo modular desacoplado.
6.  **Administra Monetización Soberana**: Procesa de manera real cuotas, retiros y licencias bajo el esquema 85/15, eliminando simulaciones visuales.

### ¿Cómo lo hace? (Flujo de Operación)

Cada instrucción o interacción ingresada al sistema pasa obligatoriamente por el **Pipeline Canónico de Procesamiento (P-R-P-D-A-A)**:

```text
  ┌──────────────┐      ┌──────────────┐      ┌────────────────┐
  │  1. PERCEIVE │ ───► │  2. REMEMBER │ ───► │ 3. POLICY GATE │  (ARGUS evalúa riesgo)
  │  sanitización│      │  memoria      │      │  allowed/      │
  │  + traceId   │      │  pentacapa    │      │  approval/denied│
  └──────────────┘      └──────────────┘      └────────────────┘
                                                      │
                                                      ▼
  ┌──────────────┐      ┌──────────────┐      ┌────────────────┐
  │   6. AUDIT   │ ◄─── │    5. ACT    │ ◄─── │   4. DECIDE    │  (C.R.O.W.N. pondera
  │  BookPI +    │      │  herramientas │      │  nodos y peso   │   ISA/SOPHIA/ORION/ARGUS)
  │  AuditBundle │      │  autorizadas  │      │  del plan       │
  └──────────────┘      └──────────────┘      └────────────────┘
```

1.  **Perceive**: Sanitiza la entrada, genera identificadores de rastreo (`traceId` y `correlationId`) y normaliza metadatos técnicos.
2.  **Remember**: Consulta de forma exclusiva las bases de conocimiento y vectores del territorio permitidos dentro del ámbito requerido.
3.  **Policy Gate (ARGUS)**: Ejecuta una validación contra el motor Aegis-X para evaluar el nivel de riesgo determinista `R`, determinando si la acción es permitida, requiere autenticación step-up/HITL o es bloqueada inmediatamente.
4.  **Decide (CROWN)**: Coordina los nodos cognitivos asignando pesos específicos a la presencia empática (**ISA Core**), el razonamiento lógico-científico (**SOPHIA Engine**) o la generación de código y soporte técnico (**ORION Engine**).
5.  **Act**: Ejecuta los servicios autorizados y consume APIs externas con un circuito protector (*Circuit Breaker*) de 8.5 segundos máximo.
6.  **Audit**: Genera un bloque inmutable que contiene el resultado, el historial, el hash del bloque anterior y el hash del bloque actual, insertándolo directamente en el ledger **BookPI** de forma indeleble.

## 5. Módulos y Funciones Detalladas

La plataforma organiza sus capacidades a través de los siguientes subsistemas:

### A. C.R.O.W.N. Gateway (Gobernanza y Enrutamiento)
*   **Orquestación de Nodos**: Arbitra el procesamiento cognitivo, balanceando las salidas según los pesos dinámicos asignados a los motores especializados.
*   **Constitutional Gate**: Evalúa si el prompt del usuario viola los preceptos de la Constitución de YUN antes de activar la inferencia.
*   **Filtro PRAXIS**: Un motor de análisis estático que intercepta código de inyección, expresiones regulares maliciosas o intrusiones.

### B. LATAM Aegis-X Gateway (Detección y Respuesta a Amenazas)
*   **Análisis Multidimensional**: Evalúa variables continuas como tasa de anomalía (`anomaly_rate`) y relación de volumen (`volume_ratio`).
*   **Doble Capa de Ejecución**: Enrutamiento prioritario hacia el núcleo nativo de Python para clasificar amenazas mediante modelos estructurados; conmutación automática al motor de cálculo TS en milisegundos si falla la infraestructura del sistema operativo.
*   **Control del Nivel Aegis**: Escala el entorno a estados defensivos rigurosos: OPEN, WATCH, CONTAIN, ISOLATE, VAULT, LOCKDOWN.

### C. SovereignDB & Memory Engine (Persistencia y Memoria)
*   **Almacenamiento Pentacapa**: Red de bases de datos locales y relacionales que segrega el almacenamiento en capas con tiempos de vida (TTL) automatizados.
*   **Libro de Eventos de Auditoría**: Almacena de forma indeleble logs técnicos, trace IDs, IPs y anomalías mapeadas, garantizando una auditoría completa del lado del servidor.

### D. Quantum Utility Platform (QUP - Procesamiento Cuántico)
*   **Fase de Mapa**: Transforma variables físicas o lógicas complejas en topologías cuánticas fermiónicas estructuradas.
*   **Fase de Optimización**: Emplea algoritmos de segmentación (*Circuit Cutting*) y redes de tensores para reducir la profundidad de los circuitos de instrucción (ISA).
*   **Fase de Mitigación**: Implementa corrección Toric QEC, mitigación de errores libre de matrices (`mthree`) y absorción de ruido Pauli para asegurar resultados legibles en simuladores e infraestructura NISQ.

### E. Monetization & Withdrawal Engine (Finanzas Comunitarias)
*   **División de Ingresos Soberana**: Aplica un contrato matemático transparente que destina el 85% de los beneficios directamente al desarrollador/creador de contenido territorial y el 15% para el sostenimiento de la infraestructura local.
*   **Registro Inmutable de Retiros**: Cada solicitud de transferencia o cobro de regalías requiere autenticación multifactor, generando un bloque indisoluble que se estampa en BookPI para evitar duplicidades de saldo o retiros fantasmas.

## 9. Puesta en Marcha y Despliegue Técnico

### Requisitos del Sistema
*   **Node.js**: Versión `≥ 20.0` (o runtime alternativo compatible como `Bun`).
*   **Base de datos**: Instancia de PostgreSQL (Supabase recomendada) con extensiones de seguridad activas.
*   **Python**: Versión `≥ 3.10` (requerido para el motor avanzado de Aegis-X, con conmutación automática a TypeScript local si no se encuentra disponible).

### Instalación Rápida

```bash
# 1. Clonar e ingresar al repositorio
git clone <url-del-repositorio>
cd <nombre-del-directorio>

# 2. Instalar dependencias del ecosistema
npm install

# 3. Configurar variables de entorno indispensables
cp .env.example .env

# 4. Iniciar el servidor de desarrollo seguro (Puerto 3000 obligatorio)
npm run dev
```
